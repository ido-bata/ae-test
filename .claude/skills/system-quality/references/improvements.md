# 要求を保存する改善関係

既知違反の不在は改善の終点ではない。比較は対象の要求・制約から導き、コード行数・抽象化数・重み付き総合点を先に目的へ置かない。

| 関係 | 適用条件 | 構成する候補 | 保存・悪化を調べるもの |
| --- | --- | --- | --- |
| I1 状態の除去 | 値が他状態から導出可能 | 保存・同期を除き導出へ移す | 履歴、永続化、計算量、応答時間、並行性 |
| I2 判断の一本化 | 同じ意味の業務規則が複数所有される | 所有境界と利用側を再構成 | 本当に同じ意味か、依存方向、変更時の波及 |
| I3 中間層の除去 | 層が独立した要求上の意味を持たない | 委譲・変換層をなくす | 互換性、隔離、セキュリティ、拡張契約 |
| I4 境界の再配置 | 一つの要求変更に同期修正が必要 | 要求と状態を所有する単位へ再分割 | トランザクション、配置、実行コスト、外部契約 |
| I5 表現の変更 | 不正状態の処理が分岐の主因 | 有効な状態・遷移を直接表現 | 入出力、復旧、直列化、移行、全操作列 |
| I6 新旧方式の統合 | 利用側が同じ機能の方式を選ぶ | 要求を満たす方式へ移行し旧方式を撤去 | 外部利用者、保存データ、必要な移行期間 |

各候補に、要求の根拠、現状、代替構成、保存条件、比較関係、実行証拠、反例、未確立条件を対応付ける。固定の報告書を新設する必要はない。既存の仕様・コード・検査に結び付ける。

現状修正案だけでなく、要求から構成した案と比較する。差が現れる実行可能な部分を検証し、移行・撤去まで全体として成立させる。複数変換を組み合わせた候補も扱い、一手改善がないことを最適性にしない。

将来の拡張は、実際のロードマップや契約に根拠がある場合に共通シナリオとして比較する。未指定の未来のために抽象化を増やさない。新要求は過去の比較関係と構造の再評価契機になる。

比較が成立しない場合、説明の巧さや票数で埋めない。欠けている意味・測定・証拠を解決する。劣位が実証された候補を、すでに実装したという理由で維持しない。
